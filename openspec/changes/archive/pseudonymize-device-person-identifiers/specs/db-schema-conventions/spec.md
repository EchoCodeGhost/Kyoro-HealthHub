## MODIFIED Requirements

### Requirement: Uniform `person` column
Every health table SHALL have a `person` column. The stored value SHALL
be a pseudonym generated by `identity_resolver`, never the string literal
`'self'`/`'partner'` or any other human-readable person identifier. Code
SHALL never use the string literal `'self'`, but always `OWN_PERSON_ID`
from `scripts/health_config.py` — `OWN_PERSON_ID` itself SHALL resolve to
the pseudonym, not the literal string `'self'`.

#### Scenario: New importer writes data
- **WHEN** a new importer inserts rows into a health table
- **THEN** it uses `resolve_person()` from `utils/base.py` or
  `OWN_PERSON_ID`, which resolves to the pseudonym, never the string
  `'self'` or another human-readable person identifier directly in code

#### Scenario: Code review finds a string literal
- **WHEN** a code review or privacy check finds the string `'self'` used
  as a person identifier in source code
- **THEN** this counts as a convention violation that MUST be fixed
  before merge

#### Scenario: Database inspection of the `person` column
- **WHEN** the `person` column of any health table is inspected
- **THEN** it contains only pseudonyms, from which no identity or
  relationship (e.g. "partner") can be inferred

### Requirement: `device_id` as a pseudonym
`devices.device_id` (primary key) as well as `device_id`/`device` columns
in `measurements` and `ppi_raw` SHALL contain a pseudonym generated by
`identity_resolver`, never a semantic device name (e.g. `polar_v3`,
`polar_m430`). Code that needs device-type-dependent logic SHALL route
through `sensor_type` (see the `identifier-pseudonymization` capability),
not through string comparison on `device_id`.

#### Scenario: New device is registered
- **WHEN** a new device is entered in `device_registry` (`registry.json`)
- **THEN** `identity_resolver` generates a pseudonym for its `device_id`,
  and all subsequent imports write that pseudonym into `health.db`, never
  the semantic name

#### Scenario: Database inspection of the `device_id` column
- **WHEN** `devices.device_id` or `measurements.device_id`/`ppi_raw.device`
  is inspected
- **THEN** the column contains only pseudonyms, from which the concrete
  device model cannot be inferred
